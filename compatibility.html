Compatibility

Compatibility means fit, not magic certainty.

The labels below are a teaching model for describing fit and uncertainty. This website does not test applications or generate real outcomes.

Pass

Known requirements appear to match the defined environment. This is not a performance or safety guarantee.

Warning

Important conditions remain uncertain or need review before an operator chooses what to do.

Blocker

A known requirement conflicts with the current environment or policy, so the proposed path should stop for review.

Reading the result

What the label tells you

In a real review, each label would need evidence and a clearly defined target. Here the three cards are explanatory examples only. A pass would not promise performance or safety; a warning would make uncertainty visible; and a blocker would identify a conflict that needs resolution.

Useful compatibility questions

  • What dependencies does the application require?
  • Which operating details matter for execution?
  • What remains uncertain or unverified?
  • Has the team documented the rationale?

Technical fit

Does the application’s requirement set match the chosen environment?

Operational fit

Can the organisation support the chosen approach and review its risks?

Uncertainty

Which details have not been checked, and who needs to resolve them?
